Promise Awaiting

Jahid Hasan July 22, 2022 6 min read

Fetching data, reading files, waiting for a timer — almost everything interesting in JavaScript is asynchronous. Promises and async/await are the tools that make that code readable. In this post we'll walk through how they work, how to handle errors, and how to avoid the mistakes that trip up most developers (including me!).

What is a Promise?

A Promise is an object that represents a value you'll have later. It's always in one of three states:

  • pending — the work is still happening,
  • fulfilled — it finished with a value,
  • rejected — it failed with an error.
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

const coinFlip = new Promise((resolve, reject) => {
  Math.random() > 0.5 ? resolve('Heads!') : reject(new Error('Tails...'));
});

coinFlip
  .then((result) => console.log(result))
  .catch((error) => console.error(error.message))
  .finally(() => console.log('Flip finished'));

From .then() chains to async/await

Chaining .then() works, but long chains get hard to follow. An async function lets you await a Promise and write the code top to bottom, as if it were synchronous. 

// With .then()
function getUserPosts(id) {
  return fetch(`/api/users/${id}`)
    .then((res) => res.json())
    .then((user) => fetch(`/api/posts?author=${user.name}`))
    .then((res) => res.json());
}

// With async/await
async function getUserPosts2(id) {
  const user = await fetch(`/api/users/${id}`).then((res) => res.json());
  const res = await fetch(`/api/posts?author=${user.name}`);
  return res.json();
}

An async function always returns a Promise — even if you return a plain value from it.

Handling errors

With await, a rejected Promise throws, so you handle it with a normal try/catch. Remember that fetch only rejects on network failures — a 404 or 500 is still a "successful" response, so check res.ok. 

async function loadProducts() {
  try {
    const res = await fetch('/api/products');
    if (!res.ok) throw new Error(`Request failed: ${res.status}`);
    return await res.json();
  } catch (error) {
    console.error(error);
    return []; // sensible fallback
  } finally {
    hideSpinner();
  }
}

Sequential vs parallel

This is the mistake I see most often. If two requests don't depend on each other, awaiting them one by one makes the user wait for both, back to back. 

// ❌ Sequential: ~2 seconds total
const users = await getUsers();     // 1s
const products = await getProducts(); // 1s

// ✅ Parallel: ~1 second total
const [users2, products2] = await Promise.all([getUsers(), getProducts()]);

The Promise combinators

Promise.all — all or nothing

Resolves with every result in order, but rejects as soon as one Promise rejects.

Promise.allSettled — I want every result

const results = await Promise.allSettled([getUsers(), getProducts(), getOrders()]);

results.forEach((r) => {
  if (r.status === 'fulfilled') console.log(r.value);
  else console.warn('Failed:', r.reason);
});

Promise.race — first to finish wins

Great for adding a timeout to any request:

const timeout = (ms) =>
  new Promise((_, reject) => setTimeout(() => reject(new Error('Timed out')), ms));

const data = await Promise.race([fetch('/api/slow'), timeout(5000)]);

Promise.any — first success wins

Ignores rejections until every Promise has failed — useful for trying several mirrors.

const fastest = await Promise.any([
  fetch('https://mirror-1.example.com/file'),
  fetch('https://mirror-2.example.com/file'),
]);

Common mistakes

1. await inside forEach

forEach doesn't wait for async callbacks, so the code after it runs too early.

// ❌ "Done" is logged before any order is saved
orders.forEach(async (order) => { await saveOrder(order); });
console.log('Done');

// ✅ One at a time
for (const order of orders) {
  await saveOrder(order);
}

// ✅ All at once
await Promise.all(orders.map((order) => saveOrder(order)));

2. Forgetting to await

const user = getUser(1);   // ❌ a Promise, not a user
console.log(user.name);    // undefined

const user2 = await getUser(1); // ✅

3. Unhandled rejections

Every Promise chain should end with a .catch() or sit inside a try/catch. Otherwise errors disappear silently in the browser or crash your Node.js process.

Wrapping up

  • A Promise is a value that will be ready later: pending, fulfilled or rejected.
  • async/await makes async code read top to bottom; use try/catch for errors.
  • Run independent work in parallel with Promise.all or Promise.allSettled.
  • Never await inside forEach — use for...of or Promise.all.
Don't just await everything — decide what can happen at the same time.
